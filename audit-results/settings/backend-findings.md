# Source backend settings audit

The source audit ran **145 offline cases, all passing**, including **93 new diagnostic cases** in `tests/test_settings_audit.py`. The base run contains 137 cases; focused supplements contain four creation-default/Google/fallback transport cases, two real-job/restart cases, and two Windows read-only/inherited-filter cases. Passing diagnostic cases confirm the observed defect; they are not acceptance tests for the desired fix. The remaining 52 cases cover existing review loops/regression protection, pause/resume, chunking, extractor filtering, reconciliation, RAG indexing/retrieval, generation settings, environment persistence, provider catalogs, and mocked update checks.

This component uses actual FastAPI settings handlers through TestClient, temporary A/B projects and registry, and mock provider responses. It does not establish native WebView or frozen-sidecar parity. ## Successful behavior and practical limits

- Every PUT-supported project scalar/model field is independently saved, loaded through a fresh app, and checked against unaffected project B, including Unicode/spaced paths. This is persistence coverage; runtime defects above remain failures for their settings.
- All six roles accept validated nested generation settings. Zero temperature/budget and false Interactions survive; unknown roles, non-dict values, temperature 3, and negative budget are rejected before a write. Clearing the complete generation map restores environment temperature. Five pipeline factories receive intended project/constructor model, fallback, temperature, thinking level, thinking budget, and Interactions arguments. Scraper transport is covered separately by its existing tests and parent audit.
- Source Google transport spies confirm disabled Interactions chooses ChatGoogle even when the global toggle is true, and both primary/fallback receive zero temperature/budget and uppercase HIGH thinking level. Actual Interactions adapter invocation uses an injected client to capture the emitted request. Fallback preserves the selected controls and records the secondary model after an injected primary error.
- Empty/whitespace/null model overrides restore environment inheritance. Null extractor filtering restores inheritance. Top-level fields beat nested config; `translated_dir` beats `output_dir`; `chunk_size_lines` beats `target_chunk_lines`.
- With inherited `NOVEL_FILTER_EXTRACTOR_ENTITIES=false`, GET exposes raw `filter_extractor_entities=null` in both top-level and nested config, plus environment text `false`; the resolver and actual runner extractor use false. A client must resolve this inherited state before rendering the toggle. Browser rendering evidence is collected separately.
- Every allowlisted global key roundtrips and clears; empty API-key inputs preserve stored credentials, explicit clear deletes them, and responses exclude all placeholder secret values. Unknown keys, control characters, composite values, and simultaneous key replacement/clear are rejected before a write. Existing provider catalog tests replace network calls.
- An actual temporary Windows `.env` marked read-only through `os.chmod(S_IREAD)` rejects PUT with HTTP 500 and preserves disk bytes and process values. The test restores the original attribute in `finally`; no ACL or system configuration is changed. This successful single-file failure behavior does not remove the reproduced multi-key partial-write defect B13.
- Saved threshold 9 requires both fidelity and style to reach 9, and saved loop cap routes to chronicling after exhaustion. Chunking triggers strictly above the configured number of nonempty lines; reassembled chunks preserve source text. RAG top-k and disabled reranking are observed at actual search invocation. Recursive subdivision settings propagate to extractor/drafter/critic/polisher.
- Settings are snapshotted when a runner is constructed. Saving chunk/patch controls does not mutate an existing runner; a subsequent runner uses the new values. A controlled actual `/api/translate/start` job holds after runner initialization, saves drafter temperature 0.3 → 0.7 and disables patch polishing, then completes with the original controls. A second actual API job uses the new controls and produces its output. A clean subprocess restart reloads externally edited defaults while the original process still holds its old model. Existing pause/resume tests verify checkpoint reuse, but changing settings during a pause is not asserted to preserve identical quality.
- Existing auto-update behavior deliberately still saves chapter summaries when character/term updates are disabled (`runner.py:447–462`); the UI/help wording should explain this narrower meaning.
- Existing review regression guard, entity reconciliation, extractor filtering and RAG indexing tests pass with mocked models. They provide controlled source runtime evidence, not provider capability or publication-quality evidence.

## Recommended order

1. Validate complete project/global writes and stop silent config fallback (B01/B02), then unify effective runtime review/quota values (B03).
2. Correct inert runtime controls and context plumbing (B09/B10/B11), then isolate dotenv resolution between projects (B05/B06).
3. Normalize inheritance and typed booleans (B04/B07/B08), then make saves atomic/coherent and detect stale writers (B12/B13/B14).
4. Make unsupported/read-only settings explicit, apply creation defaults, and expose model capabilities honestly (B15/B16/B17).

Product code has not been modified. Diagnostic tests must be converted to desired-behavior regression assertions when each defect is fixed.
